# Медиапортал КОРА — корпоративная галерея

Этот файл читается в начале каждой сессии Claude Code. До 200 строк.
Здесь только то, что нужно для разработки сайта. Подробности — в `docs/` и skills.

## Суть заказа

Отдельный проект по разработке сайта: **закрытый медиапортал для внутреннего
использования компании КОРА**. Фото и видео из жизни компании, персональные страницы
сотрудников, поиск.

Это самостоятельный заказ. Юбилейный проект «КОРА 35» — только один из источников
материала, не рамка проекта.

Оформление должно соответствовать фирменному стилю и идеологии КОРА — так же, как
остальные продукты и сайты компании.

## Фирменный стиль и идеология

Источники (пока не собраны — пополняет пользователь):

- `docs/brand/` — брендбук, логотипы, цвета, шрифты, примеры сайтов и продуктов КОРА.
- `docs/brand/ideology.md` — ценности, тон, как компания говорит о себе и людях.

Правила:

- Стиль берём **только** из этих файлов. Не придумывать цвета, шрифты и тон «по ощущению».
- Если нужного параметра нет — спросить, а не подставлять свой.
- Оформление `index.html` в этом репозитории — внутренний монитор другого проекта,
  **не** фирменный стиль. Как образец не использовать.

## Что сайт должен уметь

- Галерея фото и видео компании.
- Персональная страница сотрудника: факты из кадрового реестра + его фото и видео.
- Главная — поиск по фамилии, без витрины превью (витрина провоцирует сравнение).
- Работает на старом телефоне и медленной сети.
- Контент пополняется без программиста: правка таблицы → пересборка → выкладка.

## Принципы содержания

- **Факт вместо комплимента.** ИИ не пишет благодарностей, не сочиняет воспоминаний,
  не генерирует и не дорисовывает лица.
- Пустых блоков вида «фото отсутствует» нет: блока либо нет, либо он полный.
- Никаких счётчиков и рейтингов («12 фотографий»).
- Подробно — skill `kora-page-content`.

## Архитектура

- **Статический сайт** на Astro, без CMS и базы данных. Нечему ломаться.
- **Один источник данных** — таблица сотрудников (`people.csv`), её ведёт кадровик.
  Сборка превращает её в страницы.
- **Адреса страниц — случайные слаги** (`/p/a7f3k9m2x1`), не фамилии.
  Генерируются один раз и не меняются никогда: на них будут ссылаться QR-коды.
- **Медиа**: фото 800px JPEG q88, `loading="lazy"`; видео с `preload="none"` и постером.
- Подробно — skill `kora-portal-build`.

## Приватность и хостинг

- Сайт закрытый: **пароль на весь сайт**, `noindex`, `robots.txt` с запретом.
- **Не GitHub Pages** — он публичен всегда, даже для приватного репозитория.
  Хостинг — свой сервер, Caddy с basic auth.
- Этот репозиторий (`kogandmitry/kopa35`) **публичный**. Фото, видео, ФИО с привязкой
  к лицам, кадровые данные и пароли сюда не класть — даже превью.
- Код сайта с реальными данными — в **отдельном приватном** репозитории.

## Инструменты

| Задача | Инструмент |
|---|---|
| Генерация сайта | Astro (+ Tailwind), Node.js |
| Разбор медиаархива, поиск лиц | Python: InsightFace `buffalo_l`, HDBSCAN, OpenCV; ffmpeg |
| QR-наклейки на печать | Python: `qrcode`, `reportlab` |
| Веб-сервер, пароль | Caddy |
| Выкладка | `npm run build` → `rsync` на сервер |
| Хранение оригиналов | Яндекс Диск пользователя |

Skills проекта (открывать перед работой по теме):

- `kora-media-index` — архив → лица → кадры по людям, с ручной проверкой.
- `kora-portal-build` — сборка, деплой, пароль, QR.
- `kora-page-content` — что и как писать на страницах.

## Где что находится

| Что | Где | Кто видит |
|---|---|---|
| Оригиналы фото/видео | Яндекс Диск | только пользователь |
| Рабочая папка, превью, реестры | компьютер пользователя | пользователь и локальный Claude Code |
| Код и документы проекта | GitHub | облачные и локальные сессии |

Облачная сессия (claude.ai/code) видит только репозиторий — не Яндекс Диск
и не компьютер. Работа с медиа идёт в локальном Claude Code.

## Как работать с пользователем

- По-русски. Спокойно, просто, по-человечески, без канцелярита.
- Сначала результат, потом подробности.
- Утверждать только проверенное; непроверенное так и называть.
- Если пользователь рассуждает или спрашивает — ответить и остановиться.
  Файлы создавать, когда просят.
- Не заводить фоновые проверки, роутины и напоминания без явной просьбы.
- Перед публикацией наружу (деплой, артефакт, комментарий) — спросить.

## Как вести сессии

- Одна сессия — одна задача.
- Новая сессия не помнит переписку. Память проекта — этот файл, git и `docs/`.
- Решение, важное надолго, — одной строкой сюда. Растёт раздел — выносить в `docs/`.
