Этот файл читается в начале каждой сессии Claude Code. Держим его коротким: до 200 строк.
Подробности — в skills и в `docs/`, здесь только то, что нужно знать всегда.

## Что за проект

35-летие компании КОРА. Юбилейный проект в три этапа: подготовка (июнь–июль 2026) →
главное событие (15 августа 2026, ГЦДТ, Набережные Челны) → «третий этап»:
то, что продолжает работать после праздника.

По данным штаба, архитектура и координация проекта — Дмитрий Коган.

Сейчас в работе **галерея КОРА**: закрытый сайт с фото и видео сотрудников и
персональными страницами. В бюджете штаба это блок 5 «Коммуникации и веб»
(виртуальная галерея) и часть блока 1 «Признание достижений» (фотогалерея).

## Что лежит в этом репозитории

- `index.html` — «Штаб проекта»: дорожная карта, бюджет по блокам, задачи, команда, риски.
  Версия монитора 3.2 от 25.06.2026. Данные вшиты в JS в конце файла (`TIMELINE`, `BLOCKS`,
  `BUDGET` и т.д.). **Данные могут быть устаревшими** — событие 15.08 уже прошло,
  прежде чем опираться на цифры и статусы, уточни у пользователя.
- `docs/tools/` — заметки о внешних инструментах, которые рассматривали для проекта.

Кода галереи здесь пока нет.

## Приватность — важно

- Репозиторий `kogandmitry/kopa35` **публичный**. Никаких фото, видео, ФИО с привязкой
  к лицам, кадровых данных и паролей в него не класть — даже превью.
- Оригиналы медиаархива лежат на **Яндекс Диске** у пользователя. Они не переносятся в git.
- Готовую галерею не размещать на GitHub Pages: он публичен всегда, в том числе для
  приватных репозиториев. Хостинг — свой сервер с паролем (см. skill `kora-portal-build`).
- Для прототипа с реальными фото нужен **приватный** репозиторий или локальная папка,
  не этот.

## Где что находится

| Что | Где | Кто видит |
|---|---|---|
| Оригиналы фото/видео | Яндекс Диск пользователя | только пользователь |
| Рабочая папка, превью, реестры | компьютер пользователя | пользователь и локальный Claude Code |
| Код, тексты, решения | GitHub | облачные и локальные сессии |

Облачная сессия Claude Code (claude.ai/code) **не видит** ни Яндекс Диск, ни компьютер
пользователя — только репозиторий. Работа с медиаархивом идёт в локальном Claude Code
на компьютере пользователя.

## Как устроена галерея (принятые решения)

Подробно — в skills, здесь только суть:

- **Статический сайт**, не CMS. Генерация — Astro. Открывается быстро на старом телефоне.
- **Один источник данных** — таблица сотрудников (`people.csv`), её ведёт кадровик.
- **Случайные адреса страниц** (`/p/a7f3k9m2x1`), а не фамилии. Слаги генерируются
  один раз, до печати QR, и после этого не меняются никогда.
- **Пароль на весь сайт** + `noindex` + `robots.txt`.
- **Главная — поиск по фамилии**, не витрина превью: витрина провоцирует сравнение.
- **Факт вместо комплимента.** ИИ не пишет благодарностей, не сочиняет воспоминаний,
  не генерирует и не дорисовывает лица. Пустых блоков вида «фото отсутствует» нет.

## Как работать с пользователем

- Отвечать **по-русски**. Спокойно, просто, по-человечески: без канцелярита,
  без нарочитой «чёткости» и лишних списков.
- Сначала результат, потом подробности. Коротко, но понятно — не сжимать в обрывки.
- Если пользователь рассуждает или спрашивает — ответить оценкой и остановиться.
  Файлы и артефакты создавать, только когда просят.
- Утверждать только проверенное. Если что-то не проверено — так и сказать.
  Не выдавать догадку за факт (например, не описывать видео или файлы, которые не открывал).
- Спрашивать только когда без ответа никак: необратимые действия, смена объёма работ,
  данные, которые знает только пользователь.
- **Не заводить** автоматические фоновые проверки, роутины и напоминания без явной
  просьбы — они тратят контекст и ничего не дают.
- Перед публикацией чего-либо наружу (артефакт, комментарий, деплой) — спросить.

## Как вести сессии

- Одна сессия — одна задача: «прототип галереи», «разбор архива», «тексты страниц».
- Новая сессия не помнит прошлую переписку. Память проекта — этот файл, git и `docs/`.
- В конце сессии: коммит, короткая запись о том, что сделано и что дальше.
- Решение, принятое в разговоре и важное надолго, — переносить сюда, в CLAUDE.md,
  одной строкой. Файл не раздувать: если раздел растёт, выносить в `docs/`.
